# Jackpot reveal

A rolling number is for values that change. A **reveal** is for the one value the user has been waiting for: the credit they were granted, the cashback they claimed, the jackpot. Casinos have spent decades tuning that moment, and two presentations came out of it:

- **The win-meter rollup** (`revealStyle="count"`, the default). The figure opens at `$0` and counts itself up to the total in one decelerating sweep. Digits *swap* in place, the count's own speed is the animation, and leading digits appear as the count reaches their place, so `$923` grows into `$5,923` and then `$50,000` without anything reflowing. With **tiers** (the "big win → mega win → epic win" thresholds) the count runs tier by tier: it lands on each milestone, punches, pauses, then accelerates again.
- **The reels** (`revealStyle="spin"`). Every digit spins like a slot reel, then the reels brake and lock one at a time from the left, each with the mechanical bounce of a reel catching its stop.

Both land with a pop: a velocity kick on the figure's scale, rung out by a damped spring. All of it runs in the native engine; the JS thread is not involved once the reveal is fired.

## The `reveal` prop

`reveal` is a three-state prop:

| `reveal` | The view shows |
| --- | --- |
| `undefined` (default) | A normal rolling number. `value` changes roll. |
| `false` | The **opening frame** of `value`: its final layout with every digit blank except the mandatory ones (`$0.00`), so the box is already the right size and nothing moves when the count starts. |
| `true` | The reveal plays to `value`. Flip it back to `false` to re-arm. |

Mount with `reveal` already `true` and the reveal starts on mount (a "you just got this" takeover). A `value` that changes while the reveal is running re-targets the running count; a `value` that changes after it has landed rolls normally.

Pair it with `textAlign="center"` and a full-width `style` for a centred hero figure: while leading digits are still blank the visible run stays centred and grows outwards.

## Tiers

`revealMilestones` are numbers in the figure's units, the breakpoints a casino rollup escalates through. Milestones at or above `value` are ignored, so you can pass your fixed tier table for every reveal.

With milestones the count is shaped tier by tier, like a slot's tally:

- Every tier gets an **equal share** of `revealDuration`, whatever its size: the counter simply runs faster in a bigger tier, and the whole reveal keeps the same length.
- The first tier opens from zero on the exponential sweep; each later tier runs on an ease-in-out clock, so the counter **accelerates out of a milestone and decelerates into the next**.
- On reaching a milestone the figure **punches** (75 % of the landing pop) and, with `revealMilestoneHold`, **pauses** on it for that many milliseconds before running on. `onRevealMilestone(index, value)` fires at that moment.

The banner ("MEGA WIN"), the confetti, the coin shower and the sound sting are the app's business, in React Native, on top of the figure: `onRevealMilestone` and `onRevealEnd` give you the beats. The number itself only ever shows numbers.

```tsx
<RollingNumber
  value={win}
  reveal={reveal}
  revealMilestones={[bet * 15, bet * 30, bet * 60]}
  revealMilestoneHold={400}
  onRevealMilestone={(index) => {
    setTier(TIERS[index])   // your banner
    haptics.impact()
  }}
  onRevealEnd={() => haptics.success()}
/>
```

## Entrances, haptics, confetti

The reveal animates the figure. Everything around it composes with ordinary React Native animation:

- An **entrance pop** (the figure erupting from small) is a `transform: [{ scale }]` on a wrapper view, `withTiming(1, { easing: Easing.out(Easing.back(1.5)) })` from `0.4`, started together with `reveal`.
- The **landing haptic** goes in `onRevealEnd`; a **tier sting** in `onRevealMilestone`.
- Whatever comes after the figure (the next block of copy, the CTA) waits for `onRevealEnd`, so it never arrives while the number is still moving.

## Timing

| Prop | Default | |
| --- | --- | --- |
| `revealDuration` | `2200` | ms of the count (or until the last reel locks). Holds and the landing pop come on top. |
| `revealBounce` | `0.07` | Peak overshoot of the landing pop; `0` disables it. |
| `revealStagger` | `200` | `spin`: ms between one reel locking and the next, from the left. Shortened when the reels wouldn't fit the duration (the first reel always spins for at least 30 % of it). |
| `revealMilestones` | none | `count`: the tiers. |
| `revealMilestoneHold` | `0` | `count`: ms the count pauses on each tier. |

The curve of the count is exponential in value on a quad-eased clock: a number's perceived speed is how fast its magnitude moves, so the figure multiplies at a steady rate, tens, hundreds and thousands each get the same screen time, and the multiplication decelerates into the target. The spread (how much smaller the count opens than the target) is capped at the target divided by ten, so a small credit counts near-linearly instead of dwelling on single digits.

## Imperative

`ref.current.revealTo(value)` plays a reveal to `value` in the current style whatever the prop says. `ref.current.jumpTo(value)` **skips** a running reveal and shows the total, the "tap to slam" every casino counter has.

## Reduce Motion

Under Reduce Motion / "Remove animations" a reveal snaps to `value` at once; `onRevealEnd` still fires, so your sequencing keeps working.

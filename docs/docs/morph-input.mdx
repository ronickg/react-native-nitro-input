# Morph input

`react-native-nitro-morph-input` is the second package in this repository: a native single-line **input** whose text morphs the way [Torph](https://torph.lochie.me) morphs text on the web. Characters that stay glide to their new place, new ones slide or fade in, removed ones leave alongside their neighbours. A comma that reflows travels to where it now belongs instead of blinking into existence.

It is a real input. A system text field (`UITextField` on iOS, `EditText` on Android) owns the keyboard, editing, selection, paste and accessibility; the morph layer on top only draws its glyphs. What makes it different from a `TextInput` that formats in `onChangeText`:

- **Formatting happens natively, before a frame is drawn.** In `mode="number"` every keystroke goes through the same C++ formatter on both platforms: grouping separators, one decimal separator, at most `fractionDigits` decimals, the caret kept where you typed, a digit too many rejected outright. The JS thread only learns about the result, so there is no flicker, no caret jump and no dropped keystroke, however busy React is.
- **The same formatting model as the rolling number**: `prefix` / `suffix` at their own sizes, pinned to the top, bottom, baseline or centre of the digits; grouping and decimal separators of your choice.
- **One engine.** The matching (which characters persist, enter and leave), the slide, fade and scale curves and the timing live in `cpp/MorphEngine.cpp`, shared by Swift and Kotlin.

```sh
bun add react-native-nitro-morph-input react-native-nitro-modules

```

## An amount field

<Example
  code={`import { MorphInput } from 'react-native-nitro-morph-input'

const [amount, setAmount] = useState(NaN)

<MorphInput
  mode="number"
  prefix="$"
  prefixFontSize={28}
  affixAlign="top"
  placeholder="0"
  fractionDigits={2}
  fontSize={48}
  fontWeight="700"
  textAlign="center"
  style={{ width: '100%' }}
  onChangeValue={setAmount}          // 1234.5, or NaN while empty
/>`}>
  <MorphAmountDemo />
</Example>

Type `1234` and the field shows `$1,234`: the `1` slides over to make room as the comma arrives from below, the `4` drops in from above. Type `.5` and the decimal point and the `5` follow. Backspace over the comma and it takes the digit before it with it.

Keep the field uncontrolled and read `onChangeValue` (the number) or `onChangeText` (the formatted string), or pass `value` to drive it. A `value` that merely echoes `onChangeText` back never fights the user, native already shows it; a `value` that differs (a "Max" button, a clamp) is applied and morphs in.

## Worklets

With `react-native-worklets` installed (it ships with Reanimated 4), a `transform` worklet and worklet-marked `onChangeText` / `onChangeValue` handlers run on the UI thread *inside* the native edit, before a frame is drawn: a mask written in JS applies with no flicker, and a shared value is updated with no JS thread in between. This is the mechanism of Expo UI's worklet callbacks and react-native-transformer-text-input, with the native formatter still running first in `mode="number"`.

```tsx
const usernameTransform: MorphTransform = ({ text }) => {
  'worklet'
  const cleaned = text.replace(/[^0-9a-zA-Z_]/g, '').toLowerCase()
  return { text: cleaned ? '@' + cleaned : '' }
}

<MorphInput placeholder="@username" transform={usernameTransform} />

const progress = useSharedValue(0)
<MorphInput mode="number" onChangeValue={(value) => { 'worklet'; progress.value = value / 10 }} />
```

Without `react-native-worklets` the props are ignored with a single warning and everything else keeps working.

## How the morph decides what moves

- **Typing** (a caret is known): everything before the caret pairs by position from the left, everything after it from the right, so the edit is exactly the characters that entered or left. Grouping separators are kept out of that walk, because a comma reflows with the magnitude rather than with the keystroke; they pair from the units end instead, so the thousands comma stays the thousands comma and glides. Unless the integer gained or lost a column — then every comma belongs a group further along, past the digits that just carried the other way, so it drops out and a new one rises rather than sliding through them. Typing in the fraction leaves the integer columns alone, and the commas simply glide.
- **A value set from code** (`setValue`, `setText`, `clear`, the `value` prop): digits pair by their column from the decimal point, so `1,204 → 1,318` swaps the three low columns in place. When the integer part gained or lost columns the digits pair by subsequence from the units end and the separators leave. Plain text pairs by longest common subsequence (`Continue → Confirm` keeps `Con`).

A character that persists eases to its new x. A new digit drops in from above (a separator rises from below) through the clipped line box, fading in over the first quarter of the morph; a leaving digit drops out the same way. Text characters fade and scale (0.95×). Characters that enter or leave ride along with their nearest persisting neighbour, so a word that grows or shrinks stays one shape. Reduce Motion snaps.

Six or more adjacent characters replaced with nothing surviving between them stop being characters that moved. There is no neighbour left to travel against, and sliding each one only smears the run, so it recedes as one shape instead: no slide, and a scale to 0.8× about the run's own centre rather than each character's. The arriving run comes forward out of that same centre. This is what a three-column jump looks like — `100,000 → 100,000,000` swaps one quantity for another rather than dropping seven characters through the line box, and the commas recede with the block instead of falling like digits.

## Props

The full table is in the package [README](https://github.com/ronickg/react-native-nitro-rolling-number/tree/main/packages/react-native-nitro-morph-input#props). The ones you will reach for first:

| Prop | Default | |
| --- | --- | --- |
| `mode` | `'text'` | `'number'` formats as you type. |
| `fractionDigits`, `maxIntegerDigits` | `2`, `15` | Limits; digits past them are rejected. |
| `groupingSeparator`, `decimalSeparator` | `','`, `'.'` | |
| `prefix`, `suffix`, `affixAlign` | `''`, `''`, `'baseline'` | As on the rolling number. |
| `placeholder` | `''` | Morphed away by the first character. |
| `duration`, `easing`, `effect` | `400`, `'expo'`, `'auto'` | The morph. |
| `keyboardType`, `returnKeyType`, `autoCapitalize`, `autoCorrect`, `maxLength`, `editable`, `autoFocus` | | Input traits. |
| `transform` | | A worklet mask, run synchronously on the UI thread. |
| `onChangeText`, `onChangeValue`, `onFocus`, `onBlur`, `onSubmitEditing` | | The change handlers may be worklets. |

Imperative handle: `focus()`, `blur()`, `clear()`, `setText()`, `setValue()`, `getText()`, `getValue()`, `isFocused()`.

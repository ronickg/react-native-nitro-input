# Props

`NitroInput` takes every `View` prop (`style`, `testID`, `accessibilityLabel`, …) plus the ones below. All are optional.

A test in the package fails when this page misses a prop the component declares, so what is listed here is what the component takes. Every entry links to itself.

## Text and value

<Prop name="value" type="string">
The text to show (controlled). The native side formats and shows what the user types on its own; the prop is applied when it changes to something other than what the field already shows, so echoing `onChangeText` back into state never fights the user. A `value` carrying a stale `mostRecentEventCount` is ignored, as `TextInput` ignores it.
</Prop>

<Prop name="defaultValue" type="string">
The initial text (uncontrolled).
</Prop>

<Prop name="placeholder" type="string" default="''">
Shown while the field is empty. With `transition="reflow"` the first character reflows it away. In `'number'` mode `'0'` reads well.
</Prop>

<Prop name="placeholderTextColor" type="ColorValue" default="platform">
Colour of the placeholder.
</Prop>

<Prop name="maxLength" type="number" default="unlimited">
`'text'` mode: the most characters accepted.
</Prop>

<Prop name="editable" type="boolean" default="true">
Whether the user can edit the field.
</Prop>

<Prop name="readOnly" type="boolean" default="false">
Alias of `editable={false}`, as in React Native.
</Prop>

## Mode

One prop picks how the field edits. It is separate from `inputMode` and `keyboardType`, which only pick the keyboard. See [An amount field](/input/amount-field) and [A masked field](/input/masked-field).

<Prop name="mode" type="'text' | 'number' | 'mask'" default="'text'">
`'text'` is a plain field. `'number'` formats natively as you type: grouping separators, one decimal separator, up to `fractionDigits` decimals, a currency `prefix` / `suffix`; the value comes out of `onChangeValue` and `getValue()`. `'mask'` applies the fixed pattern in `mask`.
</Prop>

### Number mode

<Prop name="fractionDigits" type="number" default="2">
Most digits allowed after the decimal separator; a keystroke past it is rejected. `0` disables the decimal.
</Prop>

<Prop name="maxIntegerDigits" type="number" default="15">
Most integer digits accepted.
</Prop>

<Prop name="groupingSeparator" type="string" default="','">
Inserted between every three integer digits. `''` disables grouping.
</Prop>

<Prop name="decimalSeparator" type="string" default="'.'">
Placed between integer and fraction digits. Whatever the keyboard's decimal key produces (`.` or `,`) is accepted as it.
</Prop>

<Prop name="signPlacement" type="'beforeAffix' | 'afterAffix'" default="'beforeAffix'">
Where a negative amount's sign sits relative to `prefix`: `-$1,234.56`, or `$-1,234.56` with `'afterAffix'`. Only the reflow honours it; a plain field's affixes are accessory views outside the text, so it is always `'afterAffix'` there. See [Negative amounts](/input/amount-field#negative-amounts).
</Prop>

### Mask mode

<Prop name="mask" type="string" default="''">
The pattern, e.g. `'+1 ([000]) [000]-[0000]'`. `[0]` mandatory digit, `[9]` optional digit, `[A]` mandatory letter, `[a]` optional letter, `[_]` mandatory alphanumeric, `[-]` optional alphanumeric, `[…]` an unbounded run of the preceding type. `{…}` is a fixed block whose characters count towards the extracted value; a literal outside brackets is shown but not extracted. `\\` escapes. An invalid pattern leaves the field unmasked rather than breaking it.
</Prop>

<Prop name="maskNotations" type="{ character: string; characterSet: string }[]" default="[]">
Your own slot characters beyond the built-in ones: the character that stands for the slot in the mask, and every character it accepts.
</Prop>

<Prop name="maskAutocomplete" type="boolean" default="true">
Fill in constants as the caret reaches them. Only with the caret at the end, so editing mid-value does not fight you.
</Prop>

<Prop name="maskAutoSkip" type="boolean" default="false">
Backspace walks back over autocompleted constants.
</Prop>

## Affixes

Static text around the field's text, drawn at their own sizes. See [An amount field](/input/amount-field).

<Prop name="prefix" type="string" default="''">
Drawn before the text, e.g. `'$'`.
</Prop>

<Prop name="suffix" type="string" default="''">
Drawn after the text, e.g. `' USD'`.
</Prop>

<Prop name="prefixFontSize" type="number" default="fontSize">
Font size of `prefix`, e.g. a smaller currency symbol.
</Prop>

<Prop name="suffixFontSize" type="number" default="fontSize">
Font size of `suffix`.
</Prop>

<Prop name="affixAlign" type="'baseline' | 'center' | 'top' | 'bottom'" default="'baseline'">
How prefix and suffix line up with the text: `'top'` pins glyph tops, `'bottom'` the bottom of the ink, `'baseline'` shares the baseline, `'center'` centres.
</Prop>

<Prop name="prefixAlign" type="'baseline' | 'center' | 'top' | 'bottom'" default="affixAlign">
Alignment of `prefix` only.
</Prop>

<Prop name="suffixAlign" type="'baseline' | 'center' | 'top' | 'bottom'" default="affixAlign">
Alignment of `suffix` only.
</Prop>

## Frame and label

An outlined or filled box with a floating label, drawn natively. See [Frames](/input/frames).

<Prop name="variant" type="'none' | 'outlined' | 'filled'" default="'none'">
`'outlined'` strokes a rounded rectangle notched around the floating label; the notch is a real hole in the path, so whatever is behind the field shows through. `'filled'` tints the box. `'none'` leaves the border to `style`.
</Prop>

<Prop name="label" type="string" default="''">
The floating label. Needs a `variant` other than `'none'`. Also the field's accessible name when nothing else supplies one.
</Prop>

<Prop name="labelBehavior" type="'float' | 'always'" default="'float'">
`'float'` sits inline while the field is empty and unfocused and floats once it is focused or has text; `'always'` stays floated.
</Prop>

<Prop name="labelColor" type="ColorValue" default="placeholderTextColor">
Label colour at rest.
</Prop>

<Prop name="labelFocusedColor" type="ColorValue" default="focusedStrokeColor">
Label colour while focused.
</Prop>

<Prop name="labelFontSize" type="number" default="from fontSize">
Label size when floated, in points.
</Prop>

<Prop name="strokeColor" type="ColorValue" default="hairline grey">
Outline colour.
</Prop>

<Prop name="focusedStrokeColor" type="ColorValue" default="strokeColor">
Outline colour while focused.
</Prop>

<Prop name="strokeWidth" type="number" default="1">
Outline width in points, doubled while focused.
</Prop>

<Prop name="cornerRadius" type="number" default="8">
Corner radius of the frame.
</Prop>

<Prop name="fillColor" type="ColorValue">
`'filled'`: the box tint.
</Prop>

## Typography

Resolved the way `Text` resolves its style.

<Prop name="fontSize" type="number" default="32">
Font size in points.
</Prop>

<Prop name="fontWeight" type="TextStyle['fontWeight']" default="'normal'">
Font weight, as `Text`'s.
</Prop>

<Prop name="fontFamily" type="string" default="system">
Font family, as `Text`'s; bundled and expo-font fonts work.
</Prop>

<Prop name="color" type="ColorValue" default="label colour">
Text colour.
</Prop>

<Prop name="lineHeight" type="number" default="the font's">
Height of the line box in points, in the CSS sense: the total height a line occupies. Unlike `TextInput`, a line height tighter than the font is centred correctly too, and it applies to single-line and reflowing fields as well as wrapped ones.
</Prop>

<Prop name="allowFontScaling" type="boolean" default="false">
Scale the fonts with the system text size, like `Text`. Off by default so amounts keep their design size.
</Prop>

<Prop name="maxFontSizeMultiplier" type="number" default="0">
Upper bound for `allowFontScaling`, e.g. `1.3`. `0` is no cap.
</Prop>

## Size and alignment

<Prop name="autoWidth" type="boolean | 'auto'" default="false, or 'auto' when reflowing">
Whether the field sizes itself to its content. `false` takes its width from the parent the way a `TextInput` does, which is what makes it a drop-in. `true` always sizes to content. `'auto'` infers it: on unless `style` gives a `width` or `flex`, which lets an amount grow as digits arrive, and is the default with `transition="reflow"`.
</Prop>

<Prop name="textAlign" type="'auto' | 'left' | 'center' | 'right'" default="'auto'">
Where the text sits when the view is wider than it. `'auto'` is the start edge of the layout direction, as `TextInput`; `'left'` and `'right'` are absolute. See [Right-to-left](/input/react-native#right-to-left).
</Prop>

<Prop name="adjustsFontSizeToFit" type="boolean" default="false">
Scale the text down when it is wider than the view (give the view a fixed `width` in `style`), and back up when it fits again.
</Prop>

<Prop name="minimumFontScale" type="number" default="0.5">
Smallest scale `adjustsFontSizeToFit` may apply, `0`–`1`.
</Prop>

## Multiline

A wrapping field is drawn by the system view and is always `'text'` mode: `transition="reflow"`, a non-text `mode` and the affixes are ignored alongside it, with one warning each in development. See [Multiline](/input/multiline).

<Prop name="multiline" type="boolean" default="false">
Let the text wrap onto more than one line. The return key inserts a line break unless `submitBehavior` says otherwise.
</Prop>

<Prop name="numberOfLines" type="number">
Lines tall before it scrolls. Omit to grow with the content.
</Prop>

<Prop name="rows" type="number">
Alias of `numberOfLines`, matching `TextInput`.
</Prop>

<Prop name="textAlignVertical" type="'auto' | 'top' | 'center' | 'bottom'" default="'auto'">
Where the text sits in the box; `'auto'` is the top.
</Prop>

<Prop name="scrollEnabled" type="boolean" default="true">
Whether it scrolls once the text outgrows it.
</Prop>

## Keyboard and return key

<Prop name="keyboardType" type="'default' | 'number-pad' | 'decimal-pad' | 'numeric' | 'email-address' | 'phone-pad' | 'url' | 'ascii-capable' | 'numbers-and-punctuation'" default="by mode">
Keyboard to show. `'number'` mode defaults to `'decimal-pad'` (`'number-pad'` with `fractionDigits={0}`), the others to `'default'`.
</Prop>

<Prop name="inputMode" type="'none' | 'text' | 'decimal' | 'numeric' | 'tel' | 'search' | 'email' | 'url'">
React Native's alias for `keyboardType`, following the HTML attribute and mapped with React Native's own table. Ignored when `keyboardType` is given. `'none'` focuses without a keyboard, as in `TextInput`.
</Prop>

<Prop name="returnKeyType" type="'default' | 'done' | 'go' | 'next' | 'search' | 'send'" default="'default'">
Label of the return key.
</Prop>

<Prop name="enterKeyHint" type="'enter' | 'done' | 'go' | 'next' | 'previous' | 'search' | 'send'">
React Native's alias for `returnKeyType`, following the HTML attribute. Ignored when `returnKeyType` is given.
</Prop>

<Prop name="keyboardAppearance" type="'default' | 'light' | 'dark'" platform="ios" default="'default'">
iOS: a light or dark keyboard; `'default'` follows the system appearance.
</Prop>

<Prop name="enablesReturnKeyAutomatically" type="boolean" default="false">
Disables the return key until the field has text.
</Prop>

<Prop name="showSoftInputOnFocus" type="boolean" default="true">
`false` keeps focus and the caret without the soft keyboard, for a field driven by an in-app keypad.
</Prop>

<Prop name="submitBehavior" type="'blurAndSubmit' | 'submit' | 'newline'" default="'blurAndSubmit', 'newline' when multiline">
What the return key does: `'blurAndSubmit'` fires `onSubmitEditing` and dismisses the keyboard; `'submit'` fires it and keeps focus, so a form can move to the next field itself; `'newline'` inserts a line break (`multiline` only). The defaults are `TextInput`'s.
</Prop>

<Prop name="blurOnSubmit" type="boolean">
Deprecated alias of `submitBehavior`, resolved as `TextInput` resolves it: `false` means `'submit'` on a single-line field, `true` means `'blurAndSubmit'` on a multiline one. Ignored when `submitBehavior` is given.
</Prop>

<Prop name="autoFocus" type="boolean" default="false">
Focus the field when it mounts. Taken synchronously as soon as the view has a window, so on iOS a screen pushed over a focused field swaps the keyboard in place instead of dismissing and re-presenting it.
</Prop>

## Editing behaviour

<Prop name="autoCapitalize" type="'none' | 'sentences' | 'words' | 'characters'" default="'sentences'">
Auto-capitalisation in `'text'` mode.
</Prop>

<Prop name="autoCorrect" type="boolean" default="true">
Auto-correction in `'text'` mode.
</Prop>

<Prop name="spellCheck" type="boolean" default="autoCorrect">
Spell checking in `'text'` mode.
</Prop>

<Prop name="secureTextEntry" type="boolean" default="false">
Draws bullets and turns off autocorrect; the field keeps the real text for editing and autofill.
</Prop>

<Prop name="textContentType" type="string" platform="ios" default="''">
iOS `textContentType`, the autofill kind: `'username'`, `'password'`, `'oneTimeCode'`, …
</Prop>

<Prop name="autoComplete" type="string" default="''">
The cross-platform autofill hint, as `TextInput`'s. Used as `textContentType` on iOS when that is not set.
</Prop>

<Prop name="selectTextOnFocus" type="boolean" default="false">
Select all the text when the field gains focus.
</Prop>

<Prop name="clearTextOnFocus" type="boolean" default="false">
Empty the field when it gains focus.
</Prop>

<Prop name="contextMenuHidden" type="boolean" default="false">
Hides the Cut / Copy / Paste menu.
</Prop>

## Caret and selection

<Prop name="cursorColor" type="ColorValue" default="platform tint">
Caret colour.
</Prop>

<Prop name="selectionColor" type="ColorValue" default="platform tint">
Selection highlight colour.
</Prop>

<Prop name="caretHidden" type="boolean" default="false">
Hides the caret.
</Prop>

<Prop name="selection" type="{ start: number; end?: number }">
The caret or selection to apply, in code points into the (formatted) text. `onSelectionChange` reports moves in the same units.
</Prop>

## The reflow

The opt-in glyph animation: every edit reflows from the old text to the new one. See [The reflow](/input/reflow).

<Prop name="transition" type="'none' | 'reflow'" default="'none'">
How the text changes. `'none'` draws it the instant it changes: this is a text field first, and a `TextInput` does not animate its characters. `'reflow'` runs the glyph engine, so characters that stay glide to their new place, new ones slide or fade in and removed ones leave alongside their neighbours. A multiline field is always `'none'`.
</Prop>

<Prop name="duration" type="number" default="400">
Duration in ms of the reflow played on every change. `0` snaps.
</Prop>

<Prop name="easing" type="'expo' | 'easeOut' | 'easeInOut' | 'linear' | 'spring'" default="'expo'">
Timing curve of the reflow. `'expo'` is Torph's `cubic-bezier(0.19, 1, 0.22, 1)`.
</Prop>

<Prop name="bounce" type="number" default="0.15">
Overshoot of the `'spring'` easing, `0`–`1`.
</Prop>

<Prop name="effect" type="'auto' | 'slide' | 'fade'" default="'auto'">
How characters enter and leave. `'auto'`: digits and separators slide through the line box (digits from above, separators from below), other characters fade and scale.
</Prop>

## Worklets

With `react-native-worklets` installed, work can run on the UI thread inside the native edit, before a frame is drawn. See [Worklets](/input/worklets).

<Prop name="transform" type="NitroInputTransform">
A worklet that rewrites the text after every edit, synchronously on the UI thread: masks, custom formats, anything JS can express. It receives the edited text, the previous text and both selections (code point offsets) and returns the new text and optionally where the caret goes; `null` keeps the edit. In `'number'` mode it runs after the native formatter. Create it once (module scope or `useCallback`): a new function re-registers the worklet.
</Prop>

Any event handler below marked `'worklet'` runs on the UI thread instead of the JS one.

## Events

Every event is a superset of `TextInput`'s: `nativeEvent` carries React Native's fields under React Native's names, so a handler written for a `TextInput` works unchanged, and the same fields are repeated at the top level, so `({ text }) => …` reads better than `(e) => e.nativeEvent.text`.

<Prop name="onChangeText" type="(text: string) => void">
After every edit, with the field's (formatted) text. Marked `'worklet'`, it runs on the UI thread and can write shared values before the next frame.
</Prop>

<Prop name="onChange" type="({ nativeEvent: { text, eventCount, target } }) => void">
React Native's other change callback, fired alongside `onChangeText` with the same text. `eventCount` is the native edit counter, as in `TextInput`.
</Prop>

<Prop name="onChangeValue" type="(value: number) => void">
`'number'` mode: after every edit, with the numeric value; `NaN` when empty. A `'worklet'` runs on the UI thread.
</Prop>

<Prop name="onChangeMask" type="(formatted, extracted, tailPlaceholder, complete) => void">
`'mask'` mode: after every edit, with the masked text, the characters the user contributed, what is still missing, and whether every mandatory slot is filled.
</Prop>

<Prop name="onFocus" type="(event: NitroInputFocusEvent) => void">
Focused. The event carries `text`, `eventCount` and `target`.
</Prop>

<Prop name="onBlur" type="(event: NitroInputFocusEvent) => void">
Blurred. Same event as `onFocus`.
</Prop>

<Prop name="onSubmitEditing" type="(event: NitroInputTextEvent) => void">
The return key was pressed.
</Prop>

<Prop name="onEndEditing" type="(event: NitroInputTextEvent) => void">
Editing finished: focus lost or the keyboard dismissed, as `TextInput`'s.
</Prop>

<Prop name="onSelectionChange" type="(event: NitroInputSelectionEvent) => void">
The caret or selection moved. `selection`, `start` and `end` are code points.
</Prop>

<Prop name="onKeyPress" type="(event: NitroInputKeyPressEvent) => void">
A key was pressed, before the text changes: the character, `'Backspace'` or `'Enter'`.
</Prop>

<Prop name="onNativeRef" type="(ref: NitroInputRef) => void">
Receives the native Nitro object once the view is mounted.
</Prop>

## Accessibility and identity

The system field is the accessibility element, with the formatted text as its value (`$1,234.50 USD` reads as such). See [Working with React Native](/input/react-native).

<Prop name="accessibilityLabel, aria-label" type="string">
The field's name for VoiceOver and TalkBack, forwarded to the system field. `aria-label` wins over the older spelling, as in `TextInput`. Without either, `label` is used.
</Prop>

<Prop name="aria-labelledby" type="string">
Forwarded as `accessibilityLabelledBy`.
</Prop>

<Prop name="aria-busy, aria-checked, aria-disabled, aria-expanded, aria-selected" type="boolean">
Fold into `accessibilityState`, as on any view.
</Prop>

<Prop name="aria-hidden" type="boolean">
Hides the field from assistive tech, as on any view.
</Prop>

<Prop name="testID, nativeID, id" type="string">
Forwarded to the system field, the element e2e tools find. `id` wins over `nativeID`, as in `TextInput`.
</Prop>

<Prop name="style" type="ViewStyle">
The host view's style. Width comes from it unless `autoWidth` says otherwise; `direction: 'rtl'` flips a single field.
</Prop>

## Methods (`ref`)

The handle queues a call made before the native view exists and replays it once mounted, so `focus()` in an effect on mount works.

| Method | Description |
| --- | --- |
| `focus()` | Focuses the field. |
| `blur()` | Blurs it. |
| `clear()` | Empties the field; with `transition="reflow"` the characters reflow away. |
| `setText(text)` | Replaces the text (formatted in `'number'` mode), caret at the end. |
| `setValue(value)` | `'number'` mode: shows `value` formatted; `NaN` empties the field. |
| `getText()` | The field's current (formatted) text. |
| `getValue()` | `'number'` mode: the numeric value, `NaN` when empty. |
| `isFocused()` | Whether the field has focus. |
| `setSelection(start, end?)` | Moves the caret or selection; code points into the (formatted) text. |
| `native` | The native Nitro object, or `null` before mount. |

## Hook

`useNitroInputState(useSharedValue)` returns the field's `text`, `value`, `focused` and `selection` as shared values, plus the worklet `handlers` to spread onto the field that keep them current. See [the field's state as shared values](/input/worklets#the-fields-state-as-shared-values).

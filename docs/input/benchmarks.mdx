title: Benchmarks
description: 'Mount and focus cost against TextInput, measured in release builds on device.'
---

Release builds; mount is 20 fields rendered in one state update, measured to
the last `onLayout` over 5 cold passes; focus is `focus()` → `onFocus` over 12
runs. Medians.

| target | mount: MorphInput | mount: TextInput | focus: MorphInput | focus: TextInput |
| --- | --- | --- | --- | --- |
| iPhone 13 Pro Max | 12.6 ms | **9.7 ms** | **4.5 ms** | 53.7 ms |
| iPhone 17 Pro simulator | 17.2 ms | **8.8 ms** | **4.1 ms** | 29.3 ms |
| Pixel 9 Pro emulator | **24.8 ms** | 62.6 ms | **2.0 ms** | 18.4 ms |
| Pixel 10 | **30.3 ms** | 41.7 ms | **2.5 ms** | 21.9 ms |
| Galaxy A22 (slow device) | **76.4 ms** | 90.8 ms | **14.1 ms** | 24.8 ms |

On the iPhone, `NitroInput` mounts in 12.9 ms and focuses in 10.6 ms — the same
mount as `MorphInput`, because the overlay is not what mount costs.

For a third point of reference, `@expo/ui`'s SwiftUI `TextField` on the same
device mounts 20 fields in **91.4 ms** and focuses in **107.4 ms** — roughly 7x
our mount and 24x `MorphInput`'s focus, and it is invisible to
`react-native-keyboard-controller`.

**Programmatic focus is faster**, because `focus()` is a direct call into the
hybrid that lands on the next runloop turn, and `onFocus` comes back from the
field's own delegate. `TextInput.focus()` goes through `TextInputState` and a
Fabric view command applied with the mounting transaction, then returns through
the batched event emitter — about a frame's wait either side. Tapping a field
is unaffected: the OS grants first responder directly, with no JS in the loop.

**The ratio depends on the device.** On fast hardware it looks like 8–9×; on a
budget phone it is 1.8×, because MorphInput's round trip costs real CPU while
`TextInput`'s frame wait stays roughly constant. The dependable claim is
**~10 ms saved per programmatic focus on a slow device**, more on a fast one.

**Mount** is cheaper than `TextInput` on every Android target measured, and on
iOS costs about 0.16 ms more per field. That difference is not this component:
a *different* Nitro view (`RollingNumber`, no text input, fewer props) mounts at
the same 12.2 ms per 20 that `MorphInput` and `NitroInput` do, against 9.1 ms
for `TextInput` and 4.1 ms for a bare `View`. It is the per-view floor of a
Nitro `HybridView`, roughly 0.6 ms each — measured on an iPhone 13 Pro Max over
15 cold passes.

Both components deliver `onFocus` **asynchronously**; the benchmark screen
checks that rather than assuming it, so the two numbers measure the same event.
Re-run any of this from the example app's **Mount / focus benchmark** screen.

`NitroInput` registers itself in React Native's text-input registry, so the
things that act on "the focused input" work on it as they do on `TextInput`:

- `Keyboard.dismiss()`, `TextInput.State.currentlyFocusedInput()` and
  `TextInput.State.blurTextInput()`
- a `ScrollView`'s `keyboardShouldPersistTaps` / auto-blur
- `react-native-keyboard-controller`: the focused-input observer sees it,
  `KeyboardAwareScrollView` scrolls it into view, and `KeyboardToolbar`'s
  next/previous traverses into and out of it

## Focus does not take the usual route

React Native focuses an input by dispatching a codegen `focus` / `blur` **view
command**. A Nitro view has no such command on Android, so that call would be
dropped and the keyboard would stay up. `NitroInput` therefore wraps
`TextInput.State.focusTextInput` / `blurTextInput` once and routes a
`NitroInput` to its own native focus and blur; every other input is passed
straight through untouched.

Two consequences worth knowing:

- **It is not an optimisation**, but it is faster. Skipping the view command on
  the way in and the batched event emitter on the way out removes about a frame
  of waiting at each end, which is where the focus numbers in
  [Benchmarks](/input/benchmarks) come from. Tapping a field is unaffected: the
  OS grants first responder with no JS in the loop.
- **It leans on a React Native internal.** The registry lives in a private
  module, imported behind a guard: a React Native version that moves it means
  `Keyboard.dismiss()` and friends stop reaching the field, rather than a crash.

`testID` and `accessibilityLabel` are forwarded to the hidden system field —
the element VoiceOver, TalkBack and e2e tools actually interact with — and the
`placeholder` is exposed as its accessibility value while the field is empty.

:::note Layout
`NitroInput` takes its width from its parent the way a `TextInput` does. `MorphInput`
sets `autoWidth="auto"` instead and sizes itself to its content, growing as you
type; give it a `width` (or `flex`) in `style` to make it fill its parent.
:::

## Threading and motion

- Every keystroke is handled on the main thread: the formatter or the mask runs,
  the field is updated, and the morph starts if it is on. `onChangeText` reaches
  JS afterwards; nothing the user sees waits for it.
- A `value` prop carrying a stale `mostRecentEventCount` (the user typed since it
  was rendered) is ignored, like React Native's own `TextInput`.
- The system field remains the accessibility element, with the formatted text
  (`$1,234.50 USD` reads as such). VoiceOver, TalkBack, autofill, the paste menu
  and selection all work as in a plain input.
- Reduce Motion on iOS and "Remove animations" on Android snap the morph and the
  floating label.
- The view implements Nitro's `RecyclableView`.

<Example
  code={`import { MorphInput } from 'react-native-nitro-input'

const [amount, setAmount] = useState(NaN)

<MorphInput
  mode="number"
  prefix="$"
  prefixFontSize={28}
  affixAlign="top"
  placeholder="0"
  fractionDigits={2}
  fontSize={48}
  fontWeight="700"
  textAlign="center"
  style={{ width: '100%' }}
  onChangeValue={setAmount}          // 1234.5, or NaN while empty
/>`}>
  <NitroInputAmountDemo />
</Example>

Type `1234` and the field shows `$1,234`: the `1` slides over to make room as the comma arrives from below, the `4` drops in from above. Type `.5` and the decimal point and the `5` follow. Backspace over the comma and it takes the digit before it with it.

Keep the field uncontrolled and read `onChangeValue` (the number) or `onChangeText` (the formatted string), or pass `value` to drive it. A `value` that merely echoes `onChangeText` back never fights the user, native already shows it; a `value` that differs (a "Max" button, a clamp) is applied and morphs in.

## Negative amounts

The sign belongs to the amount, not to the digits after the currency symbol, so the morph draws `-$1,234.56`: the way every locale that leads with its symbol writes it. A symbol styled as an ornament, small, raised and in another colour like the one above, can read better with the sign against the digits. `signPlacement="afterAffix"` gives `$-1,234.56`.

```tsx
<MorphInput
  mode="number"
  prefix="$"
  prefixFontSize={28}
  affixAlign="top"
  signPlacement="afterAffix"
/>
```

Only the morph can choose. A plain [`NitroInput`](/input/plain-field)'s affixes are real accessory views that sit outside the text, so it always draws `$-1,234.56`.

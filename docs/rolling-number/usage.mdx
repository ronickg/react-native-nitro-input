# Usage

## Change the value, the digits roll

The only thing the view needs is a number. Every change to `value` becomes one native roll: each digit takes the shortest path to its new glyph in the direction of the change, columns that appear slide in from blank, columns that disappear slide out.

<Example
  code={`const [value, setValue] = useState(1234.5)

<RollingNumber
  value={value}
  fractionDigits={2}
  groupingSeparator=","
  prefix="$"
  fontSize={56}
  fontWeight="800"
/>

<Button title="+123.45" onPress={() => setValue((v) => v + 123.45)} />`}>
  <BasicDemo />
</Example>

A value that arrives while the wheels are still rolling doesn't restart them from rest: the roll continues with the ease-out half of its curve towards the new target, so a live ticker that updates several times a second keeps flowing.

## Timing

`duration` is the length of a roll in milliseconds (`0` snaps). `easing` picks the curve: `linear`, `easeIn`, `easeOut`, `easeInOut` (default) or `spring`, whose overshoot is `bounce` (0–1). `stagger` delays each digit's start by that many milliseconds, least significant digit first, so a change cascades like a mechanical carry.

<Example
  code={`<RollingNumber
  value={value}
  groupingSeparator=","
  fontSize={56}
  fontWeight="800"
  easing="spring"   // 'linear' | 'easeIn' | 'easeOut' | 'easeInOut' | 'spring'
  bounce={0.15}     // spring overshoot, 0–1
  duration={500}    // ms
  stagger={30}      // ms between digits, least significant first
/>`}>
  <TimingDemo />
</Example>

## Direction

By default a digit rolls **up** when the number grows and **down** when it shrinks. Force one with `direction="up"` or `"down"`, e.g. for a countdown that should always fall.

```tsx
<RollingNumber value={secondsLeft} direction="down" minimumIntegerDigits={2} />
```

## Formatting

Formatting happens on the native side so the layout is known before the first frame:

| Prop | Example |
| --- | --- |
| `fractionDigits={2}` | `1234.5` → `1234.50` |
| `minimumIntegerDigits={3}` | `7` → `007` |
| `groupingSeparator=","` | `1234567` → `1,234,567` |
| `decimalSeparator=","` | `1234.5` → `1234,5` |
| `prefix="$"` / `suffix="%"` | `$42` / `42%` |

Negative values get a leading `-` that slides in and out like a digit column. See [Currency layouts](/rolling-number/currency) for affixes at their own size.

## Typography

`fontSize`, `fontWeight`, `fontFamily` and `color` work like `Text`'s style props. Bundled fonts resolve the way they do for `Text` (by PostScript or family name on iOS, through React Native's font manager on Android, including fonts registered with `expo-font`). Digits always use tabular figures so every column has the same width.

`allowFontScaling` follows the system text size like `Text`, capped by `maxFontSizeMultiplier`. It is **off** by default so amounts keep their design size.

## Sizing

The view reports its intrinsic size from native and sizes itself. When a digit column appears the box grows right away (the view is not clipped, so nothing is ever cut off); when the settled number is narrower the box shrinks only after the roll has finished, so digits on their way out are never squeezed.

Give it an explicit `width` in `style`, plus `textAlign="right"` (or `"center"`), if you don't want the layout around it to reflow as digits appear, a counter that grows past `999` for instance:

```tsx
<RollingNumber value={count} textAlign="right" style={{ width: 120 }} />
```

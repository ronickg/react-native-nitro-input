# Fit to width

A hero amount has a box; the amount doesn't always fit it. `adjustsFontSizeToFit` scales the whole number down when the view is narrower than its content (down to `minimumFontScale`, default `0.5`) and back up, never above `fontSize`, when it fits again. The view keeps its full-size height, so the box around it never moves: only the amount scales.

<Example
  code={`// fixed box: the box never resizes, the amount shrinks and grows back to fit
<RollingNumber
  value={total}
  prefix="$"
  fractionDigits={2}
  groupingSeparator=","
  fontSize={56}
  adjustsFontSizeToFit
  minimumFontScale={0.4}
  textAlign="center"
  style={{ width: 220 }}
/>

// fit the container without a fixed width: full size until it would overflow
<RollingNumber value={total} fontSize={52} adjustsFontSizeToFit style={{ maxWidth: '100%' }} />`}>
  <FitDemo />
</Example>

## How the scale moves

The scale is computed from the content **as it is drawn right now**, half-appeared columns included, so it changes continuously in step with the roll instead of jumping when a column arrives. It is a layer transform on iOS and a canvas transform on Android: no font is rebuilt while fitting.

When the settled number is narrower than the box that was reported earlier (÷10, say), the smaller size is reported to React only after the roll has finished. Reporting it immediately would shrink the box while the outgoing digit is still on its way out, and the whole amount would visibly dip and grow back.
